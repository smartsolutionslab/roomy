# Implementation Plan: Organization Web (Office & Room Admin UI)

**Branch**: `feat/006-organization-web` | **Date**: 2026-06-09 | **Spec**: `specs/006-organization-web/spec.md`

## Summary

Add the organization SPA surface — an admin-only **offices page** that lists offices (name,
location, derived capacity, rooms) and lets an administrator **create an office**, **rename it /
change its location**, **add a room** (capacity ≥ 1), and **rename a room** — to the Angular app.
The organization API already exposes `/offices**` behind the gateway with administrator-gated writes
(ADR-0013), and the gateway route `/offices/{**}` already exists, so **no gateway change is needed**.

Unlike `005-identity-web`, the organization context has **no typed-client pipeline** yet, so this
slice first stands up the ADR-0036 machinery for organization (mirroring identity / issue #22):
`AddOpenApi` + a build-time spec emit on `organization-api`, an `@roomy/organization-data-access`
lib whose client is generated by `ng-openapi-gen`, and a CI drift gate. It also relocates the
cross-context route guards into a shared frontend lib (**ADR-0040**) so `organization-feature` can
gate its routes without importing `identity-feature`.

## Technical Context

**Language/Version**: TypeScript / Angular 22 — standalone, **signal-based**, **zoneless**,
**OnPush**, `inject()`, signal `input()/output()`, no `NgModule` (ADR-0016/0027). Backend: .NET 10.

**Primary Dependencies**: `@angular/router` (functional guards), `@angular/common/http`
(`HttpClient`, relative URLs), `@jsverse/transloco` (i18n, ADR-0024), Angular CDK for accessible
behaviours (ADR-0024). Generated client via `ng-openapi-gen` (ADR-0036). Tests:
`@testing-library/angular` + `@testing-library/user-event` on `vitest-analog` (ADR-0035).

**Backend surface (through the gateway, same-origin, ADR-0030)** — all already implemented:
- `GET /offices` → `[{ id, name, location, capacity, rooms: [{ id, name, capacity }] }]`
- `POST /offices` `{ name, location }` → `201` office / `400` / `409` (name taken)
- `PATCH /offices/{id}/name` `{ name }` → `200` office / `400` / `404` / `409`
- `PATCH /offices/{id}/location` `{ location }` → `200` office / `400` / `404`
- `POST /offices/{id}/rooms` `{ name, capacity }` → `201` room / `400` (blank/`<1`) / `404` / `409`
- `PATCH /offices/{id}/rooms/{roomId}/name` `{ name }` → `200` office / `400` / `404` / `409`
- Writes require the `administrator` role (`403` for an employee); reads require any session.

**Target Platform**: browser SPA served through the gateway (single origin, ADR-0030).

**Project Type**: Angular feature library `@roomy/organization-feature` + data-access lib
`@roomy/organization-data-access`, lazy-loaded by `apps/web` (ADR-0035).

**Constraints**: no tokens in the SPA (ADR-0013); no hardcoded strings (ADR-0024); WCAG 2.2 AA
(ADR-0024); zoneless + OnPush + signals (ADR-0016); generated, drift-gated client (ADR-0036).

## Key decisions

### D-OW1 — Stand up the ADR-0036 typed-client pipeline for organization (not hand-rolled)

Mirror identity exactly: `organization-api` gains `AddOpenApi()`/`MapOpenApi()`, the
`OpenApi:EmitDocument` skip-guards (so the emit boots through `getdocument` with no broker/DB), and
the csproj `Microsoft.AspNetCore.OpenApi` + `Microsoft.Extensions.ApiDescription.Server` references
that emit the committed `Roomy.Organization.Api.json`. `@roomy/organization-data-access` runs
`ng-openapi-gen` into `src/lib/generated`, and CI drift-gates both the spec and the generated client.
Chosen over a hand-rolled client to honour ADR-0036 and keep both contexts uniform (the reviewer
directed this).

### D-OW2 — Relocate the route guards into `@roomy/shared-feature` (ADR-0040)

`authGuard`, `adminGuard`, and `NotAuthorized` move from `identity-feature` into a new
`@roomy/shared-feature` (`type:feature`/`context:shared`); identity rewires to consume them; the new
organization routes consume the same guards and `/not-authorized` route. Behaviour-preserving move
recorded in **ADR-0040** (written first). The role check stays session-sourced
(`SessionService.currentUser().roles`), the auth redirect stays a full-page navigation to
`/bff/login` — identical to today.

### D-OW3 — A single offices page with inline affordances (no nested routes)

One routed `offices-page` lists offices and hosts the create-office form and per-office inline
edit / add-room / rename-room affordances (mirroring `admin-users-page`'s inline grant). Avoids a
detail-route hierarchy the MVP does not need; mutations refresh the affected office from the
mutation response (the API returns the refreshed office / created room) rather than refetching the
whole list. Conflicts (409) and validation (capacity `< 1`, blank name) surface as field-level,
localized, `aria-live`-announced messages.
