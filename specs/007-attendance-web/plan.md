# Implementation Plan: Attendance Web (Reserve, View, Cancel — self-service)

**Branch**: `feat/007-attendance-web` | **Date**: 2026-06-09 | **Spec**: `specs/007-attendance-web/spec.md`

## Summary

Add the attendance SPA surface — a **reserve flow** (office → room → bookable day → reserve) and a
**my-reservations page** (list past/upcoming, cancel an upcoming one, change = cancel + re-reserve) —
for an employee acting on their own behalf, to the Angular app. The attendance API already exposes
`POST /reservations`, `DELETE /reservations/{id}?date=`, `GET /reservations/mine`, and
`GET /occupancy` behind the gateway (ADR-0013), and the gateway already routes `/reservations/{**}`
and `/occupancy/{**}` to the attendance cluster.

Two gaps make this more than a pure-frontend slice, both resolved inside the attendance context:

1. **No typed-client pipeline** for attendance yet — so this slice first stands up the OpenAPI codegen
   machinery (ADR `openapi-client-codegen`, the #0036 number), mirroring identity/organization: an
   OpenAPI emit on `attendance-api`, an `@roomy/attendance-data-access` lib generated by
   `ng-openapi-gen`, and a CI drift gate.
2. **No bookable-office/room catalogue** is exposed — `GET /occupancy` requires you to already know an
   office/room id. So this slice adds a small **`GET /rooms`** read endpoint on `attendance-api`,
   served from attendance's own `Offices`/`Rooms` read models (the same models the occupancy read side
   uses), with a new `attendance-rooms` gateway route. `/offices` is unavailable as a public path —
   it is already owned by organization — hence `/rooms` (the rooms you can book, each carrying its
   office). No cross-context join (ADR-0014); no new pattern (it mirrors the existing occupancy read
   endpoint), so **no new ADR**.

The section is gated to **any authenticated employee** (NOT administrator) via the shared `authGuard`
(ADR `shared-frontend-route-guards`, the #0038 number) — no `adminGuard`. Administrator on-behalf
(AT-6) and all occupancy/calendar views (OC-1..6, `008`) are out of scope.

## Technical Context

**Language/Version**: TypeScript / Angular 22 — standalone, **signal-based**, **zoneless**,
**OnPush**, `inject()`, signal `input()/output()`, no `NgModule` (ADR-0016/0027). Backend: .NET 10.

**Primary Dependencies**: `@angular/router` (functional guards), `@angular/common/http`
(`HttpClient`, relative URLs), reactive forms (work under zoneless), `@jsverse/transloco` (i18n,
ADR-0024), Angular CDK for accessible behaviours (ADR-0024). Generated client via `ng-openapi-gen`
(ADR codegen). Tests: `@testing-library/angular` + `@testing-library/user-event` on `vitest-analog`
(ADR-0035); backend host/endpoint tests in xUnit + Shouldly.

**Backend surface (through the gateway, same-origin, ADR-0030):**
- `GET /rooms` → `[{ officeId, officeName, roomId, roomName, capacity }]` — **NEW** (this slice),
  attendance's bookable catalogue from its `Offices`/`Rooms` read models; any session.
- `GET /occupancy?officeId={id}&from={day}&to={day}` → per-room `{ roomId, name, occupied, capacity,
  isFull }` (already implemented, `004`) — used to show remaining places on the room step.
- `POST /reservations` `{ officeId, roomId, date }` → `201` / `409 room_full` /
  `409 already_reserved_today` / `409 concurrency_retry_exhausted` / `422 not_bookable` /
  `404 unknown_room` (already implemented). `onBehalfOf` is omitted (self-service only).
- `GET /reservations/mine` → `[{ reservationId, officeId, officeName, roomId, roomName, date }]`
  (already implemented, `004`).
- `DELETE /reservations/{id}?date={day}` → `204` / `403 not_owner` / `404 reservation_not_found` /
  `422 past_immutable` (already implemented).

**Target Platform**: browser SPA served through the gateway (single origin, ADR-0030).

**Project Type**: Angular feature library `@roomy/attendance-feature` + data-access lib
`@roomy/attendance-data-access`, lazy-loaded by `apps/web` (ADR-0035).

**Constraints**: no tokens in the SPA (ADR-0013); no hardcoded strings (ADR-0024); WCAG 2.2 AA
(ADR-0024); zoneless + OnPush + signals (ADR-0016); generated, drift-gated client (ADR codegen);
Europe/Berlin bookable-day rules computed client-side, server remains the authority (FR-003/004).

## Key decisions

### D-AW1 — Stand up the ADR-0036 typed-client pipeline for attendance (not hand-rolled)
Mirror identity/organization exactly: `attendance-api` gains `AddOpenApi()`/`MapOpenApi()`, the
`OpenApi:EmitDocument` skip-guards (so the emit boots through `getdocument` with no broker/DB), and the
csproj `Microsoft.AspNetCore.OpenApi` + `Microsoft.Extensions.ApiDescription.Server` references that
emit the committed `Roomy.Attendance.Api.json`. The reservation/occupancy/rooms endpoints gain
`.WithName/.Produces/.ProducesProblem` annotations. `@roomy/attendance-data-access` runs
`ng-openapi-gen` into `src/lib/generated`; CI drift-gates both the spec and the generated client.

### D-AW2 — Add an attendance-owned bookable catalogue at `GET /rooms` (new gateway route)
The reserve picker needs offices+rooms; attendance has the data (`Offices`/`Rooms` read models) but no
endpoint, and `/offices` is taken by organization at the gateway. Add `GET /rooms` →
`[{ officeId, officeName, roomId, roomName, capacity }]` (flat; the SPA groups by office), a
`ViewBookableRooms` query + `IBookableRoomsReadModel` port reading attendance's read models, and a new
`attendance-rooms` YARP route (`/rooms/{**catch-all}` → attendance cluster, `AuthorizationPolicy:
default`). Rejected: composing organization's `GET /offices` at `apps/web` (would force the reserve
page out of `attendance-feature` or take offices as an input, breaking the feature-lib-owns-its-page
pattern and context isolation). Rejected: overloading `/occupancy` or `/reservations` with a catalogue
sub-resource (conflates catalogue with figures/resource).

### D-AW3 — Remaining places on the room step come from `GET /occupancy` for the chosen day
The room step shows each room's remaining places / full flag by querying
`GET /occupancy?officeId={id}&from={day}&to={day}` once a day is chosen, so a full room is visibly
unbookable before submit (AT-3, FR-002). Capacity alone (from `GET /rooms`) is shown before a day is
chosen. The server stays the authority — a lost race still surfaces `room_full`/`concurrency_retry`.

### D-AW4 — Two routed pages, no nested detail routes
`reserve-page` (the office→room→day→confirm flow) and `my-reservations-page` (list + cancel + a
"change" affordance that routes to `reserve-page`). Both lazy-loaded under an attendance route group,
guarded by `authGuard` only. "Change" (AT-5) is a navigation from a my-reservations row into the
reserve flow after cancelling — no combined edit. Bookable-day selection is constrained client-side
(Mon–Fri, today..+14, Europe/Berlin); reserve/cancel results are `aria-live`-announced.

## Phasing (see tasks.md)

1. **Backend enablement** — attendance OpenAPI emit + endpoint annotations + CI drift gate (ADR codegen).
2. **Bookable catalogue** — `GET /rooms` endpoint + `ViewBookableRooms` query/port/read-model
   (RED→GREEN, host + read-model tests) + the `attendance-rooms` gateway route.
3. **Data-access lib** — generated client + `BookableOffice/Room`/`MyReservation` view models +
   `bookable-day` helper + `AttendanceGateway` facades.
4. **Reserve flow** (FR-001..FR-004) — office→room→day→confirm page, remaining-places via occupancy,
   client-side bookable-day rule, error surfacing; route + guard + nav entry + i18n namespace.
5. **My reservations** (FR-005..FR-008) — list past/upcoming, cancel upcoming, "change" → reserve.
6. **Polish** — WCAG 2.2 AA pass + DE/EN parity (FR-010/FR-011) + empty/error states.
